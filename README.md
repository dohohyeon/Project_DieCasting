# 🏭 다이캐스팅 공정 분석 및 품질관리 대시보드
---

## 📘 프로젝트 개요

본 프로젝트는 다이캐스팅 공정에서 발생하는 **센서 시계열 데이터와 검사 결과**를 기반으로  
1) **제품 불량(PASS/FAIL) 예측**, 2) **공정 이상 징후 탐지**, 3) **모델·데이터 모니터링(MLOps)** 을  
통합 관리할 수 있는 **실시간 품질 모니터링 대시보드**를 구축하는 것을 목표로 합니다.

- **배경**
  - 불량률은 약 4.5% 수준으로 **극단적인 불균형 데이터** 구조
  - 불량이 발생한 이후가 아니라 **발생하기 전 단계에서 공정 이상을 조기 감지**할 필요
  - 모델 성능과 데이터 분포가 시간이 지나면서 변하는지 함께 추적해야 함
- **목표**
  - 센서 데이터 기반 **불량 예측 분류 모델** 및 **HDBSCAN 이상치 탐지 모델** 개발  
  - P-관리도, Nelson Rule, ARIMA 관리도를 활용한 **통계적 공정 관리(SPC)** 적용  
  - Recall 중심으로 성능을 최적화해 **불량 누락 최소화 (ROC-AUC≈0.99, Recall≈0.96 수준)**  
  - Shiny for Python 기반의 대시보드로 **현장 작업자·품질 담당자가 바로 사용할 수 있는 도구** 제공

## 🧩 분석 데이터

다이캐스팅 공정에서 수집된 **1샷(Shot) 단위 데이터**로, 대략 다음과 같은 변수들로 구성됩니다.

| 구분 | 주요 항목 예시 |
|------|----------------|
| 기본 식별 정보 | 작업 라인(`line`), 제품명(`name`), 금형명/코드(`mold_name`, `mold_code`), 수집 일시(`date`, `time`), 일자별 생산 번호(`count`) 등 |
| 공정 상태·제어 신호 | 가동 여부(`working`), 비상 정지 여부(`emergency_stop`), 사탕 신호(`tryshot_signal`), 가열로 구분(`heating_furnace`) 등 |
| 공정 센서·조건 데이터 | 용탕 온도(`molten_temp`), 상·하 금형 온도(`upper_mold_temp1~3`, `lower_mold_temp1~3`), 슬리브 온도(`sleeve_temperature`), 냉각수 온도(`Coolant_temperature`), 저속/고속 구간 속도(`low_section_speed`, `high_section_speed`), 용탕량(`molten_volume`), 주조 압력(`cast_pressure`), 비스켓 두께(`biscuit_thickness`), 형체력(`physical_strength`) 등 연속 센서 값 |
| 시간·품질 지표 | 설비 작동 사이클 시간(`facility_operation_CycleTime`), 제품 생산 사이클 시간(`production_CycleTime`), 전자교반 가동 시간(`EMS_operation_time`), 등록 일시(`registration_time`), 양품/불량 레이블(`passorfail`) 등 |

## 🔄 워크플로우

1. **탐색적 데이터 분석(EDA)**  
   - 공정 구간별 센서 분포, 로트별 불량률, 변수 간 상관관계(히트맵 등) 탐색

2. **피처 엔지니어링 및 불균형 처리**  
   - 구간별 요약 통계(평균·표준편차·최댓값/최솟값), 시계열 기반 파생 변수 생성  
   - 불량률 4.5% 구조를 보정하기 위해 SMOTENC 등 오버샘플링 기법 적용

3. **모델링 및 평가**  
   - LightGBM 중심으로 여러 분류 모델을 비교, ROC-AUC / Recall / Precision 평가  
   - SHAP, PDP 등을 활용해 **주요 영향 공정 변수** 및 임계 영역 도출

4. **이상 탐지 및 공정 상태 진단 모듈 개발**  
   - HDBSCAN으로 정상 공정 패턴을 학습하고 각 샷의 이상 확률 추정  
   - Auto ARIMA로 센서별 관리 한계(CL/UCL/LCL)를 계산하고 Nelson Rule을 적용해  
     통계적으로 의미 있는 이상 시점을 자동 탐지

5. **대시보드 통합 및 실시간 모니터링**  
   - 실시간 스트리밍 데이터와 예측 결과·통계 지표를 Shiny 대시보드에 연동  
   - Recall, Precision, 데이터 분포 변화를 주기적으로 확인하여  
     모델과 공정 상태를 한 화면에서 모니터링

## 🤖 분석 / 모델링

- **문제 정의**
  - 타깃: 제품 단위 **불량 여부 (0: PASS / 1: FAIL)**  
  - 목적: **불량을 최대한 놓치지 않는 고재현율(High-Recall) 분류 모델** 구축
- **모델**
  - LightGBM, XGBoost 등 트리계열 모델 중심으로 실험  
  - SMOTENC 기반 오버샘플링으로 불균형 완화  
  - 최종 모델은 ROC-AUC≈0.99, Recall≈0.96 수준을 달성하도록 임계값 조정
- **이상치 탐지**
  - HDBSCAN으로 정상 공정 패턴을 클러스터링하고, 각 데이터 포인트의 이상 확률(_anom_proba) 산출  
  - 이상 확률이 높은 구간을 P-관리도 및 ARIMA 관리도와 연계해 원인 분석
- **SPC / ARIMA**
  - Auto ARIMA를 이용해 센서별 시계열 모델을 학습하고,  
    예측값 및 잔차 분포를 기반으로 CL/UCL/LCL 관리 한계 계산  
  - Nelson Rule(3σ 초과, 연속 패턴 등)을 적용해 통계적으로 유의한 이상 시점 탐지

## 📊 대시보드 구성

### 🟢 Tab 1. 실시간 모니터링

실시간으로 유입되는 공정 데이터를 기반으로 **현재 공정·품질 상태를 한눈에 파악**하는 탭입니다.

- **스트리밍 제어**
  - ▶ 시작 / ⏸ 일시정지 / 🔄 리셋 버튼으로 데이터 스트림을 제어
- **동적 센서 시각화**
  - 체크박스로 센서(용탕 온도, 주조 압력 등)를 선택하면  
    해당 변수의 실시간 추이 그래프가 즉시 생성·갱신
- **상태 알림**
  - 각 쇼트마다 HDBSCAN 기반 **이상치 상태(양호/경고)**,  
    분류 모델 기반 **품질 결과(양품/불량)** 를 실시간으로 표시
- **공정 요약 KPI 카드**
  - 이상치 탐지율, 불량 탐지율(전체/금일), 모델 예측 정확도, 일일 목표 달성률 등  
    핵심 KPI를 카드 형태로 집계·표시
- **모델 예측 피드백 시스템**
  - 모델이 “불량”으로 예측한 제품 ID와 예측 확률을 리스트업  
  - ID 클릭 시 모달 창에서 **실제 라벨(불량/정상)** 과  
    “냉각수 온도 급변”과 같은 원인 텍스트를 입력  
  - 입력된 정보는 **피드백 테이블**에 누적되어 추후 모델 개선(재학습)에 활용

---

### 🟡 Tab 2. P-관리도 기반 이상 탐지

공정의 **통계적 안정성**과 개별 변수의 이상 징후를 심층 분석하는 탭입니다.

- **HDBSCAN 이상 확률 차트**
  - 시간에 따라 이상 확률(_anom_proba)이 어떻게 변화하는지 시계열로 시각화
- **인터랙티브 P-관리도**
  - 전체 모니터링 변수 중 관리 한계(UCL/LCL)를 벗어난 비율을 P-관리도 형태로 제공  
  - 분석 구간과 로트 크기를 슬라이더로 조절, ▶ 재생 버튼으로 시간 경과에 따른 이상 비율 변화를 시뮬레이션
- **Nelson Rules 위반 목록**
  - Rule 1(3σ 초과), Rule 4(14개 연속 교대) 등 Nelson Rule 기반으로  
    통계적으로 유의한 이상 패턴을 자동 탐지하여  
    위반 시점, 위반 규칙, 해당 시점에 관리 한계를 벗어난 변수 목록을 리스트업
- **ARIMA 기반 개별 변수 관리도**
  - 위반 리스트의 “이상 원인 분석” 버튼과 연동  
  - 해당 시점에서 이상을 보인 대표 변수에 대해,  
    ARIMA 통계(`arima_stats.pkl`) 기반 CL/UCL/LCL 관리도와 실제 측정값을 비교 표시  
  - 어느 센서에서 어떤 형태의 이상이 발생했는지 **근본 원인(Root Cause) 분석**을 지원

---

### 🔵 Tab 3. 모델 성능 평가

예측 모델이 **지속적으로 신뢰 가능한지**, 데이터 분포가 변하지 않았는지 모니터링하는 탭입니다.

- **핵심 성능 지표(KPI)**
  - Recall, Precision을 최근 청크(Chunk) 기준과 전체 누적 기준으로 분리해 계산  
  - 모델 개발 단계의 Validation 성능과 비교하여 성능 저하 여부를 판단
- **자동 상태 알림**
  - Recall 또는 Precision이 3회 연속 LCL(하한 관리선) 아래로 떨어지면  
    → **“⚠️ 모델 성능 저하”** 알림 표시  
  - KS 검정 P-value가 3회 연속 0.05 미만이면  
    → **“⚠️ 데이터 드리프트 의심”** 알림과 함께 영향을 받은 변수명 표시
- **성능·드리프트 시각화**
  - 청크 단위 Recall·Precision 시계열 차트로 성능 추세를 시각화  
  - KDE Plot으로 학습 데이터 vs 최근 실시간 데이터(예: 최근 100건)의 분포를 겹쳐 표현  
  - KS 검정 P-value 시계열 차트로 통계적 분포 차이를 모니터링
